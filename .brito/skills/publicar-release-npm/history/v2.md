## Quando usar
Ao fechar uma versão do brito-cli e publicar (ex.: "vamos subir a versão"). A publicação no npm é feita pelo CI ao empurrar a tag `vX.Y.Z` (workflow `.github/workflows/desktop.yml`, Trusted Publisher, `npm publish --provenance`). Não há `npm login` local.

## Passos
1. Estado: `npm view brito-cli version`, `node -p "require('./package.json').version"`, `git branch --show-current`, `git status --short`, `git tag --sort=-v:refname | head -4`.
2. Bump sem tag: `npm version X.Y.Z --no-git-tag-version` (package.json e package-lock.json). `desktop/package.json` tem versão própria e NÃO acompanha a da CLI.
3. CHANGELOG.md: seção `## X.Y.Z — AAAA-MM-DD` com Added/Changed/Fixed. Se entradas de uma versão anterior já publicada foram coladas na nova seção por engano, confira que a anterior voltou a ter só as suas.
4. README.md e README.pt-BR.md: atualize as duas (novidades da versão, comandos, variáveis).
5. Valide: `npx tsc --noEmit`, `npm test`, `npm run build`, `npm pack --dry-run` (confira `brito-cli@X.Y.Z` e tamanho).
6. `git status --short` antes de commitar: faça `git add` só dos arquivos da release. WIP alheio (ex.: `.brito/skills/*`, `src/` não relacionado) fica de fora.
7. Commit, `git push -u origin <branch>`, `gh pr create --base main`.
8. Espere o CI: `timeout 540 gh pr checks <N> --watch --interval 20 | tail -12`.
9. `gh pr merge <N> --merge`, depois `git fetch origin main --tags` e confira a versão em `origin/main:package.json`.
10. Tag anotada no main remoto: `git tag -a vX.Y.Z origin/main -m "brito-cli X.Y.Z" && git push origin vX.Y.Z`. O workflow exige que a tag bata com o package.json.
11. Acompanhe: `gh run list --workflow desktop.yml --limit 2`, depois `gh run watch <id> --exit-status --interval 20` (cerca de 5 min). Os instaladores vão para o GitHub Release.
12. Confirme no npm: `npm view brito-cli@X.Y.Z version --prefer-online`.

## Armadilhas
- `sleep N; comando` é bloqueado pela ferramenta Bash. Use `gh ... --watch`/`gh run watch` com `timeout`, ou um loop `until <checagem>; do sleep 10; done` (com `run_in_background` se for longo).
- Depois que o job de publicação do CI termina, `npm view` ainda pode mostrar a versão antiga ou dar E404 por alguns minutos (propagação/cache). Veja no log do job `gh run view <id> --log --job <jobid>` se houve `+ brito-cli@X.Y.Z` e faça polling com `--prefer-online` antes de declarar falha.
- Não publique localmente se o CI já faz isso: seria duplicado e falharia na autenticação.
- Um comando composto interrompido pode ter aplicado parte dos passos; confira `git status`, a versão e o topo do CHANGELOG antes de repetir.
- Reverter arquivo com WIP sem salvar patch (`git diff HEAD -- <arq> > patch`) perde trabalho.

## Verificação
- tsc sem erros, `fail 0` nos testes, build ok, PR com checks verdes, workflow da tag concluído, `npm view brito-cli dist-tags.latest` igual à versão nova, Release com os instaladores.
